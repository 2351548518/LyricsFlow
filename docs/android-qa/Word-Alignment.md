# 词组对应与模型响应容错

日期：2026-11-04。

## 行为

开启“罗”并授权在线服务后，生成缺失的原文／罗马音／中文词组对应，已有整句译文和来源注音保留。拉丁字母歌词也支持中文词组对应。日中语序不同的内容按短语对齐，不承诺每个单字都有独立译词。

词组按“注音、原文、中文”三层排版，作为整体换行；同一视觉行对齐三层的边界。沿用原文已有时间戳与逐字颜色，不为语义分组虚构逐词时间。首页与全屏使用同一实现；声明式竖排主题保留整句排法。关闭“译”隐藏中文词组，关闭“罗”回到完整原文及已有整句译文。

## 两种失败原因及修复

旧协议要求模型重抄原文片段并拼接完全相等；漏空格、改标点或字符便导致整批拒绝。旧校验还会因为一行罗马音夹杂中日文字或没有有效字母而拒绝整批。

- 新请求提供带编号的字元数组，模型返回相邻的 `[start,end)` 范围。客户端从原文取片段，校验整数、范围、连续性及完整覆盖，不依赖模型抄写。兼容早期按原文片段返回的响应。
- 明确限定注音字段为拉丁字母，保留重音字符；中文仅放在译文字段。既有整句标注只作为上下文。
- 每行独立校验分组；错误分组不写入，其他行继续使用。整句注音不合格但词组有效时，从词组重建注音；两者都不合格则保留该行原有标注。
- 响应行号仍检查重复、越界和缺失，截断响应不写入。遇到部分失败提示保留整句，关闭再开启可重试，不无限自动重试。整首分组响应较大，注音请求读取超时调整为 120 秒。
- 对应关系写入歌词缓存及匹配收藏，随歌词包、完整备份和 GitHub 快照保存恢复。同一歌词记录刷新保留分组；不匹配的记录不挪用旧分组。

- 47 项 JVM 通过；完整 122 项模拟器回归通过。加入真实服务响应样本后，最新 8 项罗马音专项通过，包含真实响应解码、原文完整性、错位／非拉丁输出回退、单行失败隔离、保存备份往返、刷新、布局与开关。
- 使用用户指定文档中的 DeepSeek 服务，在终端调用 `deepseek-flash` 两轮，HTTP 200，约 3.1 秒和 4.3 秒。每轮 6 组受控样例：日文、混合中英、连续空格／标点、署名、公司名、德文；12 行均完整覆盖原文字元。第一轮响应保存在测试资源 `alignment-model-sample.json`，实际交由 Android 生产解码器校验通过。
- API Key 仅在终端进程内用于请求，未输出或写入样例、仓库及测试日志。测试原文是受控片段，不包含用户完整歌词库或快照。
- 上述检查证明格式及对齐关系可用，不能证明模型读音及词义总是准确。两轮返回在读音和措辞上也有差异，已有整句标注仍保留以便回退。
