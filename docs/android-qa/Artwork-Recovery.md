# 封面缺失修复（v1.0.4）

日期：2026-11-02；正式签名 v1.0.4（versionCode 5），本记录用于[正式发行](../releases/v1.0.4.md)。

## 检查结果

原实现只读取 `ART`、`ALBUM_ART`、`DISPLAY_ICON` 中的 Bitmap，没有读取对应的 URI，也没有封面缺失后的短期重试。Android 官方支持通过 `ALBUM_ART_URI` / `ART_URI` 等字段提供图片，见 [MediaMetadata](https://developer.android.com/reference/android/media/MediaMetadata)。因此播放器只提供 URI、稍后才补齐封面、或封面读取暂时失败时，原实现可能一直显示无封面的背景。

另一个缺口出现在元数据缓存：此前会话刷新保留旧 MediaController，以避免重复注册回调；但如果播放器漏发封面回调，旧控制器也可能一直返回缓存的元数据。重试时现在使用新的控制器实例读取元数据快照；周期刷新读取新快照，同时继续保留已有回调监听。

真机复现时确认 Spotify 未提供 Bitmap，而 `content://com.spotify.mobile.android.mediaapi/spotify:image:…?transformation=NONE` 返回 `FileNotFoundException`。已增加从同一图片 ID 到 Spotify 官方 `i.scdn.co` 的备用读取，兼容实际的 transformation 查询参数；查询参数不影响 CDN 的固定主机与图片 ID。另支持匹配音乐通知的内嵌封面，校验播放器包名、会话 token 和歌名，不用聊天通知或其他歌曲猜测封面。最终在《知らないままで》上已视觉确认蓝色封面与主题恢复。

## 修复行为

- 仅 Bitmap 非空不再代表成功。16×16 采样排除全透明、近乎均匀的中性灰占位图；缓存检测结果随 Bitmap generation 更新，保留有明暗细节的真实黑白封面。过滤在元数据候选、同曲封面记忆、通知、URI 解码及备用来源共同执行，较大灰图不能覆盖较小有效封面。
- 原播放器与精确 URI 均失败后，独立搜索 QQ / 网易云封面。沿用严格歌名、歌手、版本与时长匹配，取得对应专辑图片；不会改变歌词来源或绑定。任何来源返回灰图时继续下一来源。
- 成功封面按歌曲身份和图片地址共同缓存，最多 64 个文件 / 32MB；灰图、透明图和失败响应不落盘，避免重启后失图及不同歌曲共用动态地址串图。
- 保留最高质量的内嵌 Bitmap；缺失时按专辑封面、媒体封面、显示图标的 URI 顺序在 IO 线程读取。
- 立即尝试后，依次间隔 0.7、2、5、12 秒重试；这不是绝对完成时间，图片读取本身另有网络超时。
- 每个会话、歌曲和 URI 组合先尝试五轮。耗尽后冷却 30 秒，由现有的前台周期刷新触发后续尝试；普通进度回调不会不断重置失败预算。新歌曲、新 URI、匹配通知首次到达会重新尝试。
- 前台网络重新可用时重试缺失封面；用户点击刷新图标也会立即重试封面，不更换歌词源。后台没有新增封面定时循环，网络监听随页面生命周期注销。
- 成功后停止；切歌、切播放器或断开时取消。网络工作晚到也不能覆盖新歌，不重置歌词、播放进度和主题设置。
- 支持播放器提供的 `content://` 与 HTTPS；网络请求不携带 GitHub 或翻译凭证。限制下载为 8MB，解码缩采样到约 1536 像素内，避免主线程下载和超大图片内存开销。
- 读取失败时继续显示歌词，不弹出反复错误提示，也不使用其他歌曲的封面。
