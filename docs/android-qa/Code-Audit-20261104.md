# 代码检查与请求、渲染优化

日期：2026-11-04。

本轮结合当前未发行的词组对应及独立字号改动，检查状态管理、自动／手动标注、播放器及封面恢复、悬浮窗、来源匹配及网络层、数据编解码／备份恢复、GitHub 私有快照与更新安装路径。下面记录已确认并修复的行为，不把静态检查当作所有外部服务均可用的证明。

## 修复

| 问题 | 调整及影响 |
| --- | --- |
| 自动翻译把完整歌词对象作为去重条件；罗马音回写也能重启翻译，尤其使失败请求再次调用 | 使用独立的请求键，按歌曲、来源、原文哈希、启用状态、是否缺失、服务 URL 与模型去重。另一种标注、字号、播放进度变化不重启本类请求 |
| 旧自动翻译键未包含 URL／模型；手动请求返回后也未重新检查配置 | 修改服务或模型时自动任务取消；网络返回后再次检查歌曲、来源、授权、URL 与模型，拒绝过期结果 |
| 排队请求使用等待前的歌词副本，可能重复翻译前一个请求已补全的行；迟到结果可能覆盖现有译文 | 获得互斥锁后读取当前同一记录的最新标注；已补齐时直接返回，不访问模型或 Key。合并只填缺失字段，保留已有译文 |
| 调用层传入 120 秒，HTTP 层仍把读取超时截为 60 秒 | 上限改为 120 秒；普通来源原来的短超时不变。测试直接验证实际连接的 readTimeout |
| 播放状态每次更新都扫描歌词是否缺标注，渲染又校验不变的词组原文 | 结果绑定不可变 Lyrics／Line 实例缓存，复制出新标注时重新计算，不建立无限增长的全局缓存 |
| 每次设置变更使用三个 SharedPreferences Editor 提交 | 合并为一次编辑，减少重复写入，也使这些设置在同一次编辑中更新 |
| 上传预览包含已经捕获的字节；切换是否包含背景后仍可上传旧预览 | 选项实际变化时清除待上传字节及上传预览，要求重新预览；下载预览保持独立 |

本轮没有改动文字顺序、字号、颜色、动画和封面策略，也没有增加重试循环。

## 验证

- 47 项 JVM、128 项模拟器默认回归通过。新增 2 项标注回归及 1 项 GitHub 选项回归；已有网络策略测试补充 120 秒断言。
- 新测试检查另一种标注／字号不重启请求、模型变化与撤回授权影响请求键、排队调用读取新标注、过期配置及旧结果不覆盖当前译文，以及上传选项变化后不能发布旧预览。
- Debug／Release Lint 均 0 错误、37 项警告；R8 正式签名构建通过。
- 已覆盖安装 HONOR MLY-AN00 并冷启动，查看了三层词组、封面及阅读工具栏。模型仍可能返回部分无效分组；真机截图中正确显示了既有的“部分词组保留整句”提示，没有把它冒称为读音质量已获保证。
- 测试中的 GitHub 服务使用内存假服务，未上传用户真实快照。本轮没有重跑可选的外部歌词来源联网集成测试。

日志、正式签名本地包及截图位于忽略提交的 `dist/code-audit-20261104/`；当前包版本号仍为 1.0.6，未替换已有 GitHub 附件。
