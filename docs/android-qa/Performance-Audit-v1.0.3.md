# v1.0.3 性能与逻辑检查记录

日期：2026-11-01。对照版本：公开发布的 v1.0.2；优化版本为正式签名构建 v1.0.3（versionCode 4），本记录用于其[正式发行](../releases/v1.0.3.md)。

## 检查与修复

| 范围 | 原问题 | 本次处理 |
| --- | --- | --- |
| 暂停首页 | 暂停时仍每 500ms 更新无变化的时钟 | 暂停停止循环；播放时保持原来的逐帧/减少动态效果频率，恢复播放立即更新 |
| 悬浮窗 | 暂停、隐藏时仍每 80ms 检查并尝试渲染 | 播放且可见时保持 80ms；暂停等待原有的五分钟隐藏期限；隐藏后等待状态事件；监听屏幕与悬浮窗权限变化 |
| 悬浮窗内容更新 | 拼接字符串作为更新标记，原文和译文边界可能碰撞；逐字数据变化也可能遗漏 | 使用包含完整歌词行、已唱字位置、偏好与主题的结构化标记，同时避免频繁格式化整个偏好对象 |
| 歌曲/歌词指纹 | 多处状态观察反复计算相同 SHA-256，并逐字节调用格式化器 | 每个不可变快照只计算一次；使用直接十六进制转换，保持原指纹内容与结果兼容 |
| 当前歌词定位 | 播放帧和悬浮窗反复线性扫描歌词 | 缓存有序时间索引并二分查找；无时间、重复时间及乱序歌词保留原语义，乱序时回退线性查找 |
| 播放会话 | 每次会话刷新全部注销并重新注册回调 | 按 session token 保留已有回调，只增删变化的会话，保留原来源选择规则与兜底刷新 |
| 文件导出 | 打开系统保存框期间保留整份字节数组；Activity/进程重建后可能只剩空数组而写出空文件 | 原子暂存到不参与备份的私有目录，选择目标后流式复制，结束或取消时清理；防止当前界面的重叠导出 |
| AMLL 索引 | 解析后的搜索索引常驻内存 | 收到内存回收通知后释放解析索引；后续从原磁盘缓存恢复，保留离线重试窗口与缓存有效期 |

没有调整渐变、封面模糊、歌词排版、全屏展开/返回效果、播放动画频率或图片分辨率。

## 模拟器对照

环境：同一个 API 37 x86_64 模拟器，1080×2400；两版均为同一证书的非 debuggable release APK。

流程：暂停的内置示例 `Somewhere, softer`，位置 00:27，悬浮窗开启，默认偏好；切换版本后重新进入同一示例并开启悬浮窗，待初始过渡结束后各采集约 30 秒。采集期间无输入、无播放、无切页。Perfetto 完整覆盖约 30 秒；两个 trace 均无非零 error 统计。

| 指标 | v1.0.2 | v1.0.3 |
| --- | ---: | ---: |
| `/proc/PID/stat` 采样间隔 | 30.093s | 30.078s |
| 进程用户态+内核态 CPU ticks 增量 | 52 | 1 |
| Perfetto 主线程调度运行片段数 | 966 | 7 |
| Perfetto 主线程 CPU 时间 | 372.825ms | 2.287ms |
| 结束时 TOTAL PSS | 35,573KB | 33,154KB |

主线程运行片段计数是调度指标，不能直接等同于硬件唤醒或电池耗电。该对比证明本场景的空闲工作显著减少，不代表播放场景或整机耗电的同比降幅。PSS 是单次快照，受 GC、共享页与进程启动状态影响，不能承诺固定内存降幅。

画面对比：对同一暂停场景截图，排除系统栏后比较矩形 `(0,63)-(1080,2340)`，共 1080×2277 像素；RGB 差异包围盒为空，即此区域逐像素一致，包含悬浮窗、歌词与主页控件。

## 真机验证

HONOR MLY-AN00 已使用同一正式证书从 v1.0.2 覆盖安装 v1.0.3，没有卸载或清除数据。已观察到升级后 Spotify 播放状态接入、持续歌词渲染、切歌及已保存的逐曲来源恢复。

新版约 30 秒播放窗口的 gfxinfo 记录：1,882 帧，0 个 janky frames，95th percentile 6ms；结束时 TOTAL PSS 126,984KB。它们是此次采样的观测值。

真机旧版窗口内歌曲从《煙火裡的塵埃》切到《いつも何度でも》，不满足同曲对照条件，因此不据此计算 CPU、内存或耗电降幅。真机轻量 Perfetto 的环形缓冲只保留了尾部约 9.74s / 10.73s 调度数据，也不把它当作完整 30 秒调度对照。之后真机切到其他应用，停止触控操作。
