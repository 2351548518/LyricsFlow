# 歌词来源切换、逐曲选择与同步恢复（2026-10-28）

## 排查结论

截图中的“更新未完成，保留本地歌词”来自 `AppGraph.loadAutomatic` 的统一失败分支，具体接口错误或匹配拒绝原因被放在 `message`，但已有歌词时首页主要显示 `matchNotice`，因此用户看不到真正原因。

同时存在以下行为冲突：

- `selectSource` 在请求前写入来源偏好并修改 source，随后强制刷新、绕过可用歌词缓存；请求失败后显示来源又回到旧歌词的 source。
- `refresh` 调用完整自动匹配，开启自动换源时总是从 QQ 开始，可能覆盖刚选定的来源。
- 原有来源偏好、分来源 binding 和歌词虽然已备份，运行时自动顺序却没有优先恢复手动逐曲选择。
- 手动绑定先修改界面绑定，再等待歌词请求成功；失败时旧歌词与新绑定可能不一致。

调查时对官方 LRCLIB 的 `GET /api/search?q=勋章 鹿晗` 实际收到 HTTP 503。仅凭旧截图不能断定当时具体是接口失败、超时还是不可靠匹配，但这些失败都会被旧提示掩盖。无法保证服务端 503 被客户端修复。

## 当前行为

| 操作 | 查询与保存规则 |
| --- | --- |
| 切换来源 | 优先使用目标来源已确认记录的有效缓存；需要时仅查询目标来源。成功后才保存逐曲选择 |
| 歌曲匹配中确认候选/ID | 保存该提供方的具体记录，后续重新播放优先恢复该记录 |
| 刷新 | 重新获取当前显示来源的当前记录，绕过网络缓存，不启动全来源匹配或改变记录 |
| 重新自动匹配 | 明确按 QQ → 网易云 → AMLL → LRCLIB 重新匹配；成功后将本曲设为自动模式 |
| 切换/刷新/重新匹配失败 | 保留原歌词、来源、绑定和已保存选择，显示具体来源与原因；提供目标来源的匹配入口 |
| 新歌 | 已确认的逐曲选择优先；无逐曲选择时使用自动规则。关闭自动换源时保留旧默认来源配置的兼容行为 |
| 本地导入 | 作为逐曲选择保存；重播时直接恢复，不查询网络来源 |

刷新图标新增“刷新”文字与更明确的无障碍名称。来源选择窗说明其作用，并提供“重新自动匹配”。失败后的歌曲匹配窗口默认打开失败的目标来源，而非仍在显示的旧来源。

歌词、来源、具体记录与选择在同一数据库事务内确认；请求代次防止取消/快速切换后的旧结果覆盖新选择。曲目时长晚到时，未完成的手动请求仍按原目标重试，不悄悄回到自动首选。切换来源不会修改其他歌曲的选择。

旧提供方解析升级继续有效：来源级选择可以进行必要的原文升级；手动确认的具体记录保留该记录身份。机器/用户译文只在原文与时间仍对应时保留；新手动记录不会直接套用旧记录译文。

## 用户数据

新增 `entries.kind=selection`，以播放歌曲的稳定 metadata key 为 ID：

- 播放歌曲的标题、歌手、专辑、时长等元数据。
- 实际歌词来源。
- 具体提供方记录的完整 `Track`，包括 sourceId/songmid/AMLL 文件名、标题、歌手、专辑、时长。
- `mode=source`（固定来源并记住匹配记录）、`record`（手动确认具体记录）、`auto`（明确恢复自动模式）。
- 选择更新时间；纯粹重播/重新读取相同选择不会更新它或改变备份数据顺序。

使用 auto 记录而非直接删除选择，可以在备份恢复的合并语义下覆盖另一份旧的固定选择。来源、记录字段不一致或外来歌曲 key 会在恢复前拒绝。

旧版本 `source:<trackKey>` 只在存在同来源可用歌词/绑定时迁移，避免把历史失败尝试误当成已确认选择。缺少网络记录 ID 的旧缓存保留为来源偏好，不把空 ID 当作已确认记录，也不阻断备份。旧备份继续可导入。

`Transfer` 将 selection 与 binding、lyrics、saved、style 一并纳入用户数据；时间校准仍通过 trackPreferences 一起备份。GitHub 上传预览显示逐曲选择条数，既有私有仓库快照上传、下载、恢复使用相同验证与恢复流程。恢复当前实际播放歌曲后，会重新读取恢复的逐曲选择；缓存存在时可离线恢复，无缓存时按所存记录取歌词。

本次没有向真实 GitHub 仓库上传用户资料；新字段随下一次应用内上传一起同步。自动上传调度与跨设备按字段实时合并不在本次范围，现有预览、冲突检查及恢复副本机制保持有效。旧版本应用不认识新 selection 数据，恢复新备份应使用新版应用。

## 边界

歌曲身份仍使用当前应用的标题/歌手/专辑 metadata key。不同播放器给出完全不同译名、歌手写法或专辑时，不盲目把一首歌的固定绑定套给另一首；可重新手动确认。网络来源无记录、版权限制、接口故障或匹配不可靠时，不伪造切换成功。具体记录被上游删除且本地无歌词时，需要重新匹配。
