# 歌词校准默认 0 ms 修复

日期：2026-10-27。

默认偏移一直为 0。上一轮在 `AppGraph` 中增加 `delay(300)` 等待元数据时，Kotlin 优先解析到了同类的 `delay(Long)` 校准设置方法，导致自动匹配把 300 ms 保存为当前歌曲／来源的偏移。这是该次改动引入的错误，不是播放器需要统一补偿 300 ms。

修复：

- 将校准方法重命名为 `setLyricOffset`，等待明确写成 `kotlinx.coroutines.delay(300)`，避免同名覆盖。
- 启动时执行一次修复，只清理已有 `delay:* = 300` 记录，其他偏移保留。之后用户主动设置的 300 ms 不会再次清除。
- 校准窗口明确显示“默认 0 ms”，保留手动调整和归零。

真机安装后主动重启 LyricsFlow，确认修复标记已保存、误写的 300 ms 记录剩余 0 条；校准窗口实际显示 `0 ms`，见 [界面记录](./calibration-zero-dialog.json)。没有清空歌词库、绑定、翻译配置或其他应用数据。
