## 发现与修复

| 问题 | 原因 | 修复与验证 |
| --- | --- | --- |
| 切歌后旧搜索结果可能绑定到新歌 | 搜索面板的 query、结果和任务使用无歌曲 key 的 remember，而确认回调读取最新播放歌曲 | 按歌曲 key 重建搜索面板，取消旧任务，清空候选并更新关键词；新增 UI 回归 |
| 评论手动匹配会改写歌词绑定 | 评论页直接写入歌词使用的 `binding`，可能造成缓存歌词与记录不一致；重新进页也没有优先恢复独立评论记录 | 评论匹配写入独立 `commentBinding`；无独立记录时才兼容歌词绑定。进入评论页时同时固定歌曲和初始记录；独立记录纳入备份、校验、GitHub 快照及预览统计 |
| 收藏标记丢失或串到新歌 | 加载歌曲没有恢复 `saved`；旧歌曲异步保存结束后直接设置当前页 saved=true；删除后未更新首页 | 恢复实际收藏状态；异步回写核对歌曲 key；删除同步更新状态；新增恢复、删除和受控异步切歌测试 |
| 迟到译文可能覆盖新来源 | 歌词 hash 不包含来源，两个来源原文与时间相同时能通过旧回写检查；等待翻译锁后可能读到另一首歌 | 翻译任务捕获原始快照；回写同时核对歌曲、hash、来源；逐批检查来源及授权/服务配置。无实际付费翻译请求的测试验证相同 hash 跨来源拒绝覆盖 |
| 预览残留上一首歌状态 | 进入预览只替换部分 ScreenState 字段 | 统一 resetContent，清空匹配提示、失败目标、选择模式及收藏状态；新增回归 |

不对旧版已经被评论操作覆盖的绑定做推测性修复；新逻辑防止继续写坏，用户可以通过歌曲匹配重新确认记录。新的备份包含 `commentBinding`，旧备份仍能读取；较旧 APK 不认识此新增数据种类，应使用新版恢复。
